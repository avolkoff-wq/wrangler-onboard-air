# Прошивка

## Сборка и прошивка

| Способ | Как |
|---|---|
| Первая заливка, без установки | `bin/wrangler_air_full.bin` (загрузчик + разметка + прошивка) с адреса **0x0** через [ESP Web Flasher](https://espressif.github.io/esptool-js/) в Chrome по USB-C. Если порт не появляется: отключить, зажать G0 на Stamp-S3A, подключить USB, отпустить |
| Обновления | `bin/wrangler_air.bin` (только прошивка): меню UPDATE (Wi-Fi) или esptool по USB-C с адреса 0x10000 |
| Arduino IDE | открыть `wrangler_air/wrangler_air.ino`, плата M5Stack StampS3 (DinMeter), библиотека M5Unified, разметка памяти с двумя OTA-разделами, USB CDC On Boot: Enabled |
| PlatformIO | `pio run`, прошить: `pio run -t upload` |

**Одна прошивка (с 0.5.0)** под схему C (`power_schematic_def.png`): датчик 0-3,3 V прямо на G13, Unit 2Relay на PORT.B (G2 компрессор, G1 клапан), модуль 0-25 V на G15. То, что раньше было отдельными сборками, теперь в меню:

| Пункт меню | Что делает | Сохраняется |
|---|---|---|
| `[x] VALVE` | клапан спуска стоит: DEFLATE, LEARN DEFLATE, IO TEST VALVE. Без галки выход клапана всегда выключен | да |
| `[ ] DEMO` | виртуальные колёса вместо датчика, для стола. Справа вверху горит DEMO | нет, при каждом включении выключен |
| `[x] VALVE CHECK` | в покое давление ровно падает 0,008-0,1 bar/с, а оба выхода выключены: ERR VALVE OPEN (клапан или его реле залипли). Один раз за эпизод, как PUMP CHECK | да |
| `[x] PUMP CHECK` | контроллер сигнал на компрессор не даёт, а давление растёт: больше 0,5 bar за 20 с или выше 5 bar. На экране NO SIGNAL, PRESSURE RISING и красное AUX2 ON? ELSE A RELAY IS STUCK, частая низкая серия, один раз за эпизод | да |
| `OFFSET MAX` | потолок поправки потока при подкачке. **AUTO** (по умолчанию): 1,5 × выученная поправка + 0,1 bar, в пределах 0,3-1,5; пока ничего не выучено, 0,6. Поправка замеряется после каждой остановки (линия при остановке минус статика), не через c, поэтому неверная c потолок не сдвигает. Вручную: 0,30-1,50 bar. Сейчас видно в меню, на экране VERSION (`max`), в логе BOOT и STOP (`offcap`) | да |
| `[x] VOLT CHECK` | читать AUX1 через модуль 0-25 V. Мотор считается заведённым от 13,2 V, заглушенным только ниже 13,0 V (гистерезис 0,2 V, без дёрганья у порога) | да |
| `AUX1 TRIM` (0.6.0) | подогнать AUX1 под мультиметр: на экране вольты AUX1, ручкой ±0,05 V, нажатие сохраняет поправку (0,85-1,15). Без модуля или без напряжения три писка | да |
| `[x] ENGINE CONFIRM` | третье нажатие перед подкачкой, если мотор заглушен или напряжения нет | да |
| `[x] WATCHDOG` | перезапуск при зависании прошивки дольше 5 с, выходы при этом выключаются | да |

Старый вариант с датчиком 0,5-4,5 V через делитель на G1 убран: у него G1 и G13 поменяны местами, и неверный выбор в меню подал бы сигнал на ножку, куда подключён выход датчика.

Распиновка разъёмов и Grove: `docs/pinout.md`, лист `electrical/connectors_pinout.png`.

Особенности датчика на G13:
- 0 bar = 0 V, поэтому обрыв не виден по напряжению. Пин G13 подтянут к земле, обрыв читается как 0 bar,
  и его ловят две проверки: компрессор работает 3 с, а датчик меньше 0,1 bar → ошибка SENSOR; нет роста 0,1 bar за 60 с → LEAK.
- Выше 3,10 V (≈ 11,3 bar) → ошибка датчика.
- G13 и G15 читаются через драйвер ESP-IDF с кодом ошибки (`adc2.h`, 0.5.4): ADC2 делится с радио, неудачное чтение
  выбрасывается, а не считается 0 V. Меньше 6 удачных из 8 дольше 0,5 с → ERR SENSOR. AUX1 без удачного чтения 1 с = «нет модуля».
  Число сбоев за прогон: `adc_fail` в END и последнее поле `io`.
- Фильтры датчика и AUX1 считают время, а не проходы цикла (0.6.0): постоянные 90 и 390 мс при любой скорости цикла.
  Самый долгий проход цикла за прогон: `loop_max_ms` в END.

### Результат прогона и ошибки (0.6.0)

- **OFF TARGET** (оранжевым, три коротких низких): прогон закончился, но статика дальше 0,05 bar от цели. Раньше в этом случае
  был DONE и длинный «успешный» писк. С клапаном перекачка теперь спускается обратно и в обычной накачке.
- Добивка (top-up) больше не идёт вслепую по времени: останавливается по оценке давления, как основная накачка (с 1,5 с после пуска).
  В логе STOP `by=EST` или `by=TIME`.
- Основная накачка всегда останавливается не позже 2,98 bar: сильно отрицательная выученная поправка больше не даёт ложную ERR OVER у цели 3,0.
- Ошибка на любом экране (меню, SENSOR, HOURS ...) сразу звучит и открывает главный экран (кроме CALIBRATE и Wi-Fi UPDATE).
- Звуки не блокируют прошивку (`sound.h`): нажатие STOP срабатывает сразу, даже пока звучит писк.
- CALIBRATE и Wi-Fi UPDATE сначала выключают выход IO TEST; во время калибровки USB `k1 on`, `valve on`, `pulse` отклоняются.
- В строке BOOT причина перезапуска (`reset=POWERON|BROWNOUT|TASK_WDT|...`), при просадке питания ещё событие `BROWNOUT_RESET`.
- G13 на ADC2: при включённом Wi-Fi не читается. Wi-Fi включается только в режиме UPDATE, выходы при этом выключены.
- Клапан спуска K4 на G1 (PORT.B, реле 1 Unit 2Relay), работает только с галкой VALVE.

**Температура воздуха не учитывается.** При большом перепаде температуры давление меняется примерно на 0,3 %/°C, обучение на реальной системе частично это компенсирует.

## Спуск (вариант C)

- Цель выбирается ручкой из типовых давлений (`config.h` PRESETS): HIGHWAY 2.5, ROUGH ROAD 1.8, GRAVEL 1.5, TRAIL 1.2, ROCK 1.0, SAND 0.8, RECOVERY 0.5 bar и последним CUSTOM, своё значение (по умолчанию 2,0 bar), во всех сборках. На CUSTOM нажатие сначала открывает значение: ручкой шаг 0,1 bar, нажатие сохраняет и взводит старт, долгое нажатие отменяет. Ниже 0,8 bar на экране `LOW` (без бэдлоков шина может сойти с диска).
- Старт в два нажатия (см. «Управление»), потом замер статики. В пределах ±0,1 bar от цели ничего не делает (`OK, WITHIN 0.1`). Ниже цели качает компрессором (`INF`), выше спускает клапаном (`DEF`).
- Спуск: клапан открывается на время t = τ · ln(p_абс / p_цели_абс), закрывается, пауза, замер, при необходимости ещё (до 4 раз).
  Первый спуск, пока τ не выучена, проходит только 60 % пути. Если спустил ниже цели, добивает короткой подкачкой компрессором.
- Компрессор и клапан никогда не включены вместе. При пропадании питания клапан закрыт (NC).
- Две независимые калибровки: подкачка (offset, c, rate, kTop, bias, dev) и спуск (τ). Обе уточняются на каждом обычном цикле.

## Шина и стартовые значения (меню TYRE)

| | 255/75R17 | 285/70R17 |
|---|---|---|
| Воздух, 4 колеса | ≈ 210 л | ≈ 248 л |
| Подкачка ARB CKMTA12 (174 л/мин при 0 bar, 132 при 2 bar) | 1,2 → 2,4 bar ≈ 1,9 мин | ≈ 2,2 мин |
| Спуск, τ из модели (4 золотника + клапан Ø4, ≈ 5,9 мм²) | ≈ 179 с: 2,4 → 1,2 bar ≈ 1,3 мин, → 0,8 ≈ 1,9 мин | ≈ 212 с |

Это оценки ±40 %, только для первого цикла. При смене размера всё выученное пересчитывается по объёму (скорости ~1/V, τ ~V), обучение не сбрасывается.

## Лог (все сборки)

На флеше пишется CSV: включения, каждый запуск, каждая остановка компрессора / клапана с цифрами в момент остановки, каждый статический замер,
как сдвинулись выученные поправки (`старое>новое`), калибровка по манометру, итог запуска. При 200 kB файл уходит в `log_old.csv`, хранятся два последних.

Скачать: меню `WIFI: UPDATE + LOG` → телефон к сети `WranglerAir` (пароль по умолчанию `jeepjeep`, меню WIFI PASSWORD) → http://192.168.4.1 → «Download log». Там же «Clear log».

| Событие | Что в нём |
|---|---|
| BOOT | версия, шина, объём, все выученные значения и калибровка на момент включения |
| RUN / MODE | цель; начальная статика и выбранный режим INF / DEF |
| STOP | фаза (CAL_PULSE, MAIN, TOPUP, VENT), время, давление в линии, оценка, поправка, скорость, запас |
| STATIC | после какой фазы, давление, сколько ждали успокоения |
| LEARN_INF / LEARN_DEF | что намерено и как изменились offset, c, rate, kTop, bias, dev / τ |
| LEARN_TEST / LEARN_INF_TEST / LEARN_DEF_TEST | тест из меню LEARN: давление до и после, rate / τ было>стало |
| OUTPUT_TEST | импульс из меню OUTPUT TEST: выход (K1 / VALVE), давление до и после |
| FILTER_RESET | фильтры почищены: сколько часов было с прошлой чистки |
| ARM_CANCEL | взведённый старт снят: KNOB, LONG, TIMEOUT, NO_AIR |
| CAL_POINT / CAL_DONE / CAL_FAIL | точки манометра и новая линия калибровки |
| END | результат (DONE, IN_BAND, STOPPED, ERR_...), p0, итог, пуски, открытия клапана, время |

**Стенд без датчика:** меню `DEMO`. Виртуальные колёса отвечают и на компрессор, и на клапан: пока K1 включён, давление растёт, на ходу датчик показывает больше на поправку. Весь алгоритм проверяется на столе, только DinMeter. Реле при этом щёлкают по-настоящему.

## Графики работ

- Каждая работа (и тесты LEARN) записывается: раз в 0,5 с время, давление датчика (с калибровкой), оценка во время подкачки, фаза, компрессор, клапан; отдельными строками результаты статических замеров. В шапке режим, цель, p0, итог, результат, загрузка и время старта, шина, пуски, открытия клапана, длительность.
- Пока идёт работа, запись в памяти, на флеш (`/runs/r<загрузка>_<номер>.csv`) один раз в конце. Хранятся последние 20 работ, не больше ~24 kB на работу, это примерно 8 мин, как таймаут работы (дальше запись останавливается, в шапке `truncated=1`).
- Страница Wi-Fi (меню `WIFI: UPDATE + LOG` → http://192.168.4.1): список работ, новые сверху (режим, цель, p0 → итог, результат, длительность, пуски, клапан). По ссылке график прямо в браузере, без интернета: линия давления, цель пунктиром, оранжевые полосы работы компрессора, синие полосы открытого клапана, точки статических замеров, единицы как в меню UNITS. Там же скачать CSV. «Clear runs» стирает графики, «Clear log» лог, обновление прошивки как раньше.
- Живого графика нет: при включённом Wi-Fi вход датчика (ADC2) не читается.
- Пример из настольной симуляции: `screen/run_graph_example.html` (пишет `test/run.sh`).

## Стенд по USB

- USB-лог, поток LIVE и команды есть всегда, в той же `bin/wrangler_air.bin`.
- Подключить DinMeter кабелем USB-C к ноутбуку: `pio device monitor -b 115200` или `python3 tools/serial_log.py <порт> bench.csv` (порт: macOS `/dev/cu.usbmodem*`, Linux `/dev/ttyACM0`, Windows `COM5`). Нужен `pip install pyserial`, для графика ещё `matplotlib`.
- В USB идёт каждая строка лога (как в CSV на флеше), а во время работы, LEARN, OUTPUT TEST и калибровки дважды в секунду `LIVE,t,bar,est,phase,k1,valve`.
- Команды (строкой, регистр не важен): `status` (давление, вольты датчика, состояние, выученные значения, моточасы), `log` (оба файла лога), `runs` (список трасс), `run <id>` (одна трасса), `clear` (стереть лог, трассы остаются), `pulse k1`, `pulse valve` (импульс 1 с), `k1 on|off`, `valve on|off` (держать до 30 с, вместе никогда), `fake <bar>` / `fake off` (датчик «показывает» набранное давление, на экране FAKE, после перезапуска сбрасывается), `io` (одна строка: давление, вольты пина и AUX1, выходы, состояние, сбои ADC2), `ui` (экран как данные, то же, что пойдёт телефону по BLE), `press` / `hold` / `left` / `right` (нажатие, удержание 2 с, шаг ручки: через ту же очередь, что ручка и будущий телефон), во время работы выходы не трогаются, `help`.
- **Приложение для стенда на Mac:** `tools/bench_app.html`, открыть в Chrome → Connect → порт `usbmodem…`. Кнопки выходов, ползунок FAKE, живые давление / G13 / AUX1, график за 2 минуты с полосами компрессора и клапана, консоль, сохранение лога. Ничего не ставится.
- Сторожевой таймер 5 с (меню `[x] WATCHDOG`, включён по умолчанию): если прошивка зависла, DinMeter перезапускается, компрессор и клапан выключаются; после этого на экране WATCHDOG RESET, в логе WATCHDOG_RESET.
- На экране любой ошибки большое число - текущее давление в линии (живое), видно, падает оно или растёт.
- Звуки: высокий тон = хорошо (один длинный: цель достигнута, два коротких: уже было в пределах). Низкий тон = смотри экран: любая ошибка три коротких низких, ERR OVER частая низкая серия ~2 с (подойти сразу).
- `tools/serial_log.py <порт> out.csv --plot`: пишет `LIVE` в CSV, после Ctrl+C рисует давление, цель, полосы компрессора и клапана. `--plot-only out.csv` рисует сохранённый файл, `--cmd "pulse k1"` отправляет команду при старте.
- В машине ноутбук на своей батарее, не от прикуривателя.

## Управление

Все надписи на экране только латиницей (решение владельца, кириллица не нужна).


- Поворот: режим (HIGHWAY ... RECOVERY, CUSTOM).
- Нажатие считается, только если кнопку отпустили быстрее 0,5 с. Отпустил между 0,5 и 2 с: ничего.
- Старт в два нажатия: первое нажатие (только когда на экране INFLATE или DEFLATE) взводит, внизу белое `PRESS AGAIN: START` и полоска 3 с. Если будет работать компрессор (INFLATE, а также подтверждение LEARN INFLATE), над ней оранжевое `ENGINE ON?`: только напоминание, двигатель не проверяется. Второе нажатие за 3 с запускает. Поворот ручки, долгое нажатие или 3 с без нажатия снимают взвод, ничего не происходит (в логе `ARM_CANCEL` с причиной).
- Во время работы любое нажатие останавливает, без подтверждения: короткое и среднее при отпускании, удержание через 2 с (меню при этом не открывается).
- Долгое нажатие = удержание 2 с: меню. С 0,3 с удержания внизу заполняется полоска `HOLD FOR MENU`. Во время работы не действует. Те же 2 с для отмены CUSTOM, выхода из LEARN, Wi-Fi и калибровки.
- Экран всегда на полной яркости.
- Счётчик моточасов: считаются секунды работы компрессора (работа, LEARN INFLATE, калибровка) и открытого клапана, в NVS (`cmpSec`, `ventSec`) сохраняются в конце каждой работы. Меню `HOURS` (после VERSION): компрессор всего, с последней чистки фильтров, клапан, в формате ч:мм. Нажатие: назад. Удержание 2 с: экран подтверждения `FILTERS CLEANED?`, ещё раз удержание 2 с обнуляет счётчик с последней чистки (в логе `FILTER_RESET`). После 10 ч работы компрессора с последней чистки (`FILTER_SERVICE_H`) на главном экране мелкое оранжевое `CLEAN FILTERS`, старт не блокирует. В книжной ориентации надпись по очереди с подсказкой внизу. Часы пишутся в лог в BOOT и END.
- Внизу каждого экрана серая подсказка, что сейчас делают ручка и кнопка (`turn: mode  press: start  hold: menu`, `press: STOP`, `press: back` и т. д.).
- Меню `IO TEST` (после SENSOR): `COMPRESSOR (K1)` / `VALVE (K4)` (только с галкой VALVE) / `BACK`. Нажатие на пункт: выход включён (не дольше 30 с, обратный отсчёт), ещё нажатие: выключен. Включён только один выход, второй принудительно выключен; во время работы не действует. На экране живое давление, вольты G13 и AUX1. Подсказка `press: on / off (30 s max)  turn: choose  hold: back`. В логе `OUTPUT_TEST`: выход, давление до и после. Среднее нажатие (0,5-2 с) только выключает. Время включения идёт в счётчик моточасов. Старт работы выключает выход IO TEST (в логе `OUTPUT_TEST ... cut=RUN_START`). По USB то же: `k1 on|off`, `valve on|off`, импульс 1 с: `pulse k1`, `pulse valve`.
- Меню `LEARN` (после CALIBRATE): `LEARN INFLATE` (компрессор 15 с), `LEARN DEFLATE` (клапан 20 с, только в сборке с клапаном), `BACK`. Нужно давление больше 0,15 bar (иначе `CONNECT SYSTEM`), для спуска не меньше 1,5 bar (иначе `PUMP UP TO 1.5 FIRST`). Подтверждение нажатием, долгое: назад. Замер, один импульс фиксированной длины, замер. Подкачка учится как первый калибровочный импульс; спуск сразу ставит τ = 20 / ln(p_до_абс / p_после_абс) (проверка 5..3000 с), без усреднения. На экране итог (τ или rate), нажатие: назад. Нажатие во время теста: стоп. В логе `LEARN_INF_TEST` / `LEARN_DEF_TEST`.

## Алгоритм подкачки (4 колеса разом, мотор заведён)

1. Замер без потока.
2. Качает без пауз, колёса ≈ датчик − поправка.
3. Стоп за 0.1 bar до цели, 2 с замер без потока.
4. При недоборе одна добивка, длина = (цель − p) / скорость.
5. Поправка уточняется: новая = 0.7 × старая + 0.3 × измеренная, хранится в памяти (Preferences).
6. Первая подкачка: калибровочный импульс 15 с.

Спуск (этап 3): та же логика, колёса ≈ датчик + поправка спуска. K1 и K4 никогда не включены одновременно.

## Защиты

- Ошибка датчика: G13 выше 3,10 V (≈ 11,3 bar). Нижнего порога нет: обрыв читается как 0 bar и ловится так: компрессор работает 3 с, а датчик меньше 0,1 bar → ERR SENSOR.
- Давление выше 3.0 bar: стоп, ERR OVER. Проверяется оценка колёс во время подкачки и статический замер выше 3,05 bar после нашей подкачки (живая линия сразу после остановки ещё несёт поправку потока, по ней раньше была ложная ERR OVER у цели 2,7-3,0).
- Поправка потока AUTO ограничена сверху (меню `OFFSET MAX`): неверно выученная c или забитая линия иначе прятали реальное давление. Запас: сырая линия выше 3,0 + потолок + 0,1 bar после начала подкачки тоже ERR OVER.
- Обрыв сигнального провода ловится и по сырому значению (0 V), не только по откалиброванному: ноль калибровки calB больше не маскирует обрыв.
- Низкое напряжение AUX1 (меньше 11,5 V 2 с при работающем компрессоре) останавливает и работу (ERR LOW VOLTAGE), и IO TEST / `k1 on` (выход выключается), и подкачку калибровки (CALIBRATION FAILED).
- Значения из памяти (NVS) проверяются при загрузке: NaN или вне диапазона заменяются стартовыми.
- Нет роста 0.1 bar за 60 с: утечка или шланг не подключён, стоп.
- Таймаут 8 минут.

## Калибровка

Меню, 4 точки: 0, ~1, ~2, ~3 bar. Программа качает до точки, водитель вводит показание стрелочного манометра энкодером, программа идёт дальше. Итог: линейная аппроксимация методом наименьших квадратов.

- Если какая-то точка дальше 0,1 bar от линии (`CAL_FIT_MAX`, обычно опечатка в показании манометра): CALIBRATION FAILED, старая калибровка остаётся.
- Первое нажатие на CAL 1/4 включает компрессор, поэтому как в LEARN INFLATE: при заглушенном двигателе или без модуля 0-25 V нужно ещё одно нажатие (ENGINE CONFIRM).
- Во время подкачки калибровки прерывает и короткое, и среднее нажатие. PUMP CHECK и VALVE CHECK на это время выключены.

## Обновление

- Основное: пункт меню «Обновление», DinMeter поднимает свою точку Wi-Fi, в браузере 192.168.4.1 загружается .bin.
- Запасное: USB-C на DinMeter.
- Точка Wi-Fi: `WranglerAir`, пароль по умолчанию `jeepjeep`. Меняется в меню WIFI PASSWORD: 8 знаков A-Z / 0-9, ручкой по одному, нажатие дальше, на восьмом сохраняет (NVS, лог WIFI_PASS). Пароль показан на экране UPDATE.
- Если 10 минут нет ни одного запроса из браузера, Wi-Fi выключается сам (лог `WIFI timeout=1`), экран возвращается на главный.
- Две копии программы (OTA-разделы) и откат: новая прошивка по Wi-Fi помечается рабочей только после 30 с нормальной работы. Если она до этого упала или зависла (сторожевой таймер), загрузчик возвращает старую. Прошивка по USB проверки не ждёт.
- Во время загрузки по Wi-Fi сторожевой таймер подкармливается, прерванная загрузка сбрасывается, повтор работает без перезапуска.
- Пока включён Wi-Fi, датчик и AUX1 не читаются (ADC2), а команды USB `k1 on`, `valve on`, `pulse` отклоняются.
- На время обновления G2 и G1 LOW (оба выхода выключены).
- Калибровка и поправки в отдельной области памяти, переживают обновление.

## 0.2.0: fewer compressor starts

- Flow offset while pumping: **AUTO** learns `offset = c × rise rate`; **MANUAL** uses a fixed value. Menu → OFFSET (AUTO or 0.05-1.50 bar).
- Settle before a measurement: **AUTO** waits until the reading is steady: least-squares slope over the last 1 s below 0.005 bar/s on two checks in a row (every 0.25 s), 1-6 s; **MANUAL** uses a fixed time. Menu → SETTLE (AUTO or 1.0-10.0 s).
- The stop margin adapts to how well earlier stops landed. Top-up time is learned separately.
- Timers on screen (tenths of a second): the whole run time and the number of starts at the top, a countdown on pauses (settle, measure, learning pulse, top-up), a stopwatch while pumping. Calibration shows a countdown on the pause and a stopwatch while pumping.
- Calibration result reads "Sensor reads 1.2% low / Zero: 0.02 bar high / Accuracy +/-0.02 bar" instead of a= b=.
- VERSION shows the learned values: off, c, rate, top, bias, dev, settle, starts.
- Menu → SCREEN turns the picture 90 degrees: WIDE, PORTRAIT, WIDE 180, PORTRAIT 180. All screens lay themselves out for the chosen orientation.
